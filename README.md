# 2.4G 设备电量托盘

一个**极轻量**的 Windows 托盘小工具：直接读取 2.4G 无线接收器的私有 HID 通道，
显示鼠标 / 键盘的真实电量。**不装驱动、不装运行库、不用 Electron。**

- 常驻内存：**空闲 2~3 MB，正在用约 30 MB**（官方驱动动辄 500 MB ~ 1 GB）
- 依赖：**无**。只用 Python 标准库 + ctypes 调 Win32 / GDI / hid.dll
- 界面：托盘图标（按电量变色）+ 悬停提示 + 点击弹出小卡片
- 低电量提醒：跌破 20% 弹一条 Windows 系统通知（点通知也能打开卡片）

> **想要更轻的版本？** → [**C 版**](https://github.com/ahutsunboy/2.4g-battery-tray-c)：
> 同样的界面和功能，用 Win32 重写，单个 81 KB 的 exe，零运行时依赖，
> 私有内存 2.5 MB 量级。不用装 Python。

---

## 为什么不是网页版

原本想直接扩展现有的网页工具（项目早期写的 WebUSB / WebHID 查看器），
但这条路在这两台设备上**走不通**，原因很明确：

Chrome 的 WebHID 有一份硬编码黑名单
（[WICG/webhid `blocklist.txt`](https://github.com/WICG/webhid/blob/main/blocklist.txt)），
其中包含：

```
{usagePage:0x0001, usage:0x0002},  // 鼠标
{usagePage:0x0001, usage:0x0006},  // 键盘
```

只要一台 HID 设备里有**任一**顶级集合命中这些规则，浏览器就**不会把它列进设备选择框**，
页面拿不到设备句柄，也就无法读写厂商通道。

而这两台设备恰好都是「厂商通道和键鼠集合挂在同一个接口上」：

| 设备 | 接口 | 同一接口内的集合 |
|---|---|---|
| 迈从 G3 接收器 `258A:0138` | MI_01 | 键盘 `0x01/0x06` + 厂商 `0xFF00/0xFF01/0xFF02` + 多媒体 `0x0C/0x01` |
| 狼蛛 FN75 接收器 `3554:FA09` | MI_01 | 键盘 `0x01/0x06` + 鼠标 `0x01/0x02` + 厂商 `0xFF02/0xFF04` |

→ 整个接口都被屏蔽。所以只能走本机原生 HID（和厂商驱动同一个路径）。

## 从 GitHub 拉下来怎么跑

### 1. 取代码

```bat
git clone https://github.com/ahutsunboy/2.4g-battery-tray-python.git
cd 2.4g-battery-tray-python
```

没装 git 就在仓库页点 **Code → Download ZIP**，解压后进目录。

注意：仓库里**不含 exe，也不含 Python 解释器**，下面两步要自己准备。

### 2. 准备 Python（不需要 pip install）

整个项目只用标准库 + `ctypes` 调 Win32 / GDI / `hid.dll`，
**一条 pip 命令都不用执行**。只需要一个 `pythonw.exe`（Python 3.9 或更高）。
三种做法任选：

| 方式 | 做法 |
|---|---|
| 装官方 Python | 安装时勾选 **Add python.exe to PATH**，装完 `pythonw` 就在 PATH 里 |
| 便携版 | 把含 `pythonw.exe` 的整个运行时目录放到仓库根下的 `runtime\`，之后整个文件夹能拷到 U 盘 |
| 已有环境 | `pythonw` 已经在 `PATH` 里就行 |

启动器按这个顺序找 `pythonw.exe`：

1. `runtime\pythonw.exe`（便携版放这里，整个目录可拷走）
2. `PATH` 里的 `pythonw`
3. `D:\software\codingApp\miniconda\pythonw.exe`（开发者本机的兜底，别人的机器上没有，忽略即可）

验证：在 cmd 里执行 `where pythonw`，能打印出一个路径就对了。

### 3. 启动

双击 **`启动.vbs`**（无黑框，推荐）或 **`启动.bat`**。

托盘区出现一个电池图标 → 左键点开卡片，悬停看提示 →
右键图标 → 开机自动启动 / 低电量提醒 / 查看日志 / 退出。
Windows 11 默认会把它收进 `^` 隐藏图标区，拖到任务栏上即可常显。

| 文件 | 作用 |
|---|---|
| `启动.vbs` | 静默启动（推荐，双击即可） |
| `启动.bat` | 启动；`启动.bat --print` 只打印它将使用的 pythonw 路径，不启动 |
| `调试启动.bat` | 带控制台启动，能看到 Python 的报错 |
| `退出.bat` | 强制结束（平时请用托盘右键 → 退出） |

**开机自启**：托盘图标右键 → 勾选「开机自动启动」
（写入 `%APPDATA%\...\Startup\2.4G电量托盘.vbs`，取消勾选即删除）。

### 4. 双击了没反应怎么办

先双击 **`调试启动.bat`** —— 它保留一个控制台窗口，报错会直接打在上面。
按顺序排查：

1. 跑 `启动.bat --print`，看它找到的是哪个 `pythonw`
2. 跑 `where pythonw`，没有输出就是 PATH 没配好
3. `python --version` 低于 3.9 就换一个
4. 已经有一个实例在跑（单实例互斥），先在托盘右键退出再启动

│      刚刚更新                            │

│  🖱   迈从 G3 鼠标                        │
│      45% 电量                            │
│      ▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░        │

- **托盘图标**：电池形状，绿色（≥45%）/ 琥珀（20~44%）/ 红色（<20%）/ 蓝色+闪电（充电）
  多设备时取**电量最低**的那一台
- **悬停提示**：只有名称和电量 —— `狼蛛 FN75 键盘 100%  ·  迈从 G3 鼠标 45%`
  （不放时间，避免提示框太啰嗦；要时间就看卡片）
- **左键单击**：弹出卡片；**再点一次图标**、**点了卡片以外的任何地方**、
  或按 **Esc** 都会收起，不做常驻悬浮窗
- **右键菜单**：开机自动启动 / 低电量提醒 / 查看日志 / 退出
- **系统通知**：电量跌破阈值时弹一条 Windows 通知，点它能直接打开卡片

> 「点别处收起」是靠 `WH_MOUSE_LL` 低级鼠标钩子实现的：在鼠标按下那一刻拿到
> 全局坐标，判断是否落在卡片外。不能只靠 `WM_ACTIVATE`——卡片是 `WS_POPUP`，
> 在很多情况下根本拿不到激活状态，那条失焦消息永远不会来（这正是早期版本
> 「点了别处不消失」的原因）。钩子只在卡片显示期间挂着，收起即卸载。

## 刷新节奏

| 设备 | 方式 | 节奏 |
|---|---|---|
| 键盘（可主动查询） | 主动发查询指令 | 每 **10 分钟** 一次 |
| 鼠标（只能被动播报） | 阻塞等待接收器推送 | **实时**，帧到即刷 |

鼠标这一条是真的实时：线程直接阻塞在 `ReadFile` 上（内核等待，不占 CPU），
接收器一推帧就立刻返回并刷新界面。10 分钟轮询只作用于键盘这类「问一句答一句」的设备。

## 低电量提醒

任何一台设备跌破阈值，就弹一条 **Windows 系统通知**（原生 toast 横幅，带提示音）：

> 🔋 **设备电量不足**
> 迈从 G3 鼠标 剩余 18%，建议尽快充电（点击查看详情）

点这条通知 → 直接弹出电量卡片，能看到是哪台设备、还剩多少。

### 什么时候弹

| 规则 | 说明 |
|---|---|
| 阈值 | 电量 **≤ 20%** |
| 次数 | 每台设备**只弹一次**，不会反复骚扰 |
| 重新武装 | 电量回升到 **≥ 25%**（充过电 / 换电池）后，再次跌破才再弹 |
| 迟滞带 | 21~24% 这个区间**不改变状态**，所以 19%→22%→19% 不会再弹 |
| 多台同时低 | 合并成**一条**通知，电量更低的那台排在前面 |
| 充电中 | 不打扰 |

阈值和开关都在 `tray/settings.json`：

```json
"low_battery": { "enabled": true, "threshold": 20, "rearm": 25 }
```

- `enabled` 也可以用右键菜单切换（那个勾选项就是这个字段）
- 改完保存，**5 秒内自动生效**，不用重启
- `rearm` 必须大于 `threshold`，否则程序会把它顶到 `threshold + 1`
- 删掉整个文件 = 恢复出厂设置（下次启动生效）

### 为什么只能「只弹一次」，而不能做到「掉到 19% 就马上弹」

键盘每 10 分钟才被问一次，鼠标要等你动它、且接收器约 48 秒才推一帧。
**通知的触发时刻只能跟着数据到的那一刻走**，做不到「电量一掉就立刻响」。
所以设计成「跨过阈值只提醒一次」，比反复弹更符合实际数据节奏。

### 已知限制

- **专注助手 / 勿扰模式会静默吞掉通知**，API 仍然返回成功，程序也检测不到。
  同理，系统设置里关掉「通知」或把这台 pythonw 的通知权限关掉，也收不到。
- 通知头部的应用名显示为 **Python**（pythonw 的进程身份）。想改成自定义名字需要
  注册带 AppUserModelID 的快捷方式，会破坏「整个目录拷走就能用」的便携性，故不做。
- Windows 11 的这类横幅是**瞬时**的：消失后不会留在通知中心，所以要在它还在的时候点。
- 设备拔掉重插时，如果被识别成一个新的设备实例，武装状态会重置，可能补弹一次。
- 若设备处于休眠但上次读到的是低电量，**不会**重复弹（离线帧会被直接忽略，
  这一点很重要 —— 否则每次休眠都会误报一次）。

## 已适配设备与协议

这两台设备的协议是逐字节逆出来的，写法都在 `tray/battery_hid.py` 里。

### 狼蛛 FN75 键盘 — `3554:FA09`（Compx / 中颖方案）

- 通道：usage page `0xFF02`，Report ID **0x13**，输入/输出各 19 字节
- 查询：发送 `13 05 01` + 16 个 `00` + `19`（共 20 字节）
- 应答：先回 `13 05 01 ...`（握手），再回 `13 0A 01 00 04 05 XX YY ...`

| 偏移 | 含义 |
|---|---|
| `payload[6]` | **电量百分比** |
| `payload[7]` | `1` = 2.4G 在线，`0` = 离线/休眠 |

实机回包：`13 0A 01 00 04 05 64 01 ...` → `0x64` = **100%**，在线。

### 迈从 G3 鼠标 — `258A:0138`（SinoWealth / 中颖）

- 通道：usage page `0xFF02`、usage `0x0002`，**接收器主动推送**，Report ID **0x09**
- 推送周期：**约 48 秒**一帧（实测 5 分钟内 5 次，间隔 47.9~48.0 秒）
- 两种帧：

| 帧 | 含义 |
|---|---|
| `09 0A 05 XX 00 00 00 00` | **电量帧**，`XX` = 电量百分比 |
| `09 0A 02 01 00 00 00 00` | 状态帧（非电量），忽略 |

实机功率：`09 0A 05 2E ...` → `0x2E` = **46%**（与用户实际电量吻合）。

> 注意：这台鼠标**没有可用的查询指令**（7 字节 feature 通道
> `0xFF00/0x05`、`0xFF01/0x0A` 的回读值是固定缓存，不随写入变化），
> 只能等接收器自己上报。所以刚启动时鼠标可能显示 `--`，
> 最多 48 秒后就会出现真实电量，之后一直沿用最近一次上报值。

> 另外 `06 A0 02 3F ...` 这一帧（`0x3F` = 63）**不是**电量，
> 是另一类状态回包 —— 一开始差点被它带偏，是用「用户实际电量 ≈ 45%」
> 这条真值才排除掉的。

### 想加新设备？

`tray/battery_hid.py` 里继承 `DriverBase`，实现 `open()` / `poll()` 即可：

```python
class MyMouseDriver(DriverBase):
    key = "my-mouse"
    label = "某品牌鼠标"
    ids = [(0x1234, 0x5678)]      # VID, PID
    usage_page = 0xFF00            # 厂商通道
    needs_write = True

    def poll(self, timeout_ms=2000):
        self.handle.write(bytes([0x05, ...]))        # 发查询
        data = self.handle.read(8, 200)              # 收应答
        return Reading(battery=data[3], online=True, raw=_hex(data))
```

再把它加进 `DRIVERS = [CompxKeyboardDriver, MchoseDongleDriver, MyMouseDriver]`。

`tray/devices.json` 可以把 VID:PID 映射成好记的名字：

```json
{ "names": { "1234:5678": "我的新鼠标" } }
```

## 内存都花在哪

用 `_dev/_dev_mem_probe.py` 和 `_dev/_dev_mem_breakdown.py` 实测（miniconda Python 3.14，x64）：

| 阶段 | 私有提交 | 说明 |
|---|---:|---|
| 空白 `pythonw.exe` | 12.2 MB | **这就是地板**，什么都没干 |
| + 标准库（ctypes/threading/json…） | 14.6 MB | 约 +2.2 MB |
| + 本项目模块 | 15.3 MB | 我的代码只占 **0.7 MB** |
| 实际运行（窗口 + GDI + 线程 + HID） | 18~19 MB | +3~4 MB |
| 任务管理器显示（工作集） | 30~33 MB | 含共享的系统 DLL 页面 |

**结论：约 84% 是 CPython 解释器本身，不是我的代码。**
所以「再优化代码」的空间非常有限——下面的优化基本已经到顶了。

### 已经做的四件事

1. **`traceback` 延迟导入**：顶层 `import traceback` 会连锁拉起 `linecache` →
   `tokenize` → `re`，裸解释器实测 **+1.07 MB**，而这个程序正常运行永远走不到异常分支。
   改成 `_dump_exc()` 里按需导入。
2. **`gc.freeze()` + 放宽阈值**：启动期对象（窗口类、字体、笔刷、图标）之后不再变动，
   冻结后 GC 不再逐轮扫描，回收次数从每秒数次降到几十秒一次。
3. **重绘节流**：卡片里「N 分钟前」是分钟级文案，原来每 0.8 秒重绘一次，
   现在 4 秒一次 —— 肉眼无差别，GDI 调用少 5 倍。
4. **空闲归还工作集**（收益最大）：面板关着且 `idle_seconds` 内没有任何变化时，
   调 `SetProcessWorkingSetSize(-1,-1)` 把闲置页面还给系统。
   实测 **工作集 30.3 MB → 2.5 MB**。

   要诚实说明：**私有提交量一点都不变**（还是 18 MB），只是把暂时不碰的页面
   踢出物理内存，下次打开卡片靠缺页调回来（多几十毫秒，实测感觉不到）。
   这正是托盘程序该有的取舍：长期不占着内存，用到时再热。
   想让它一直保持热态、追求最快响应，把 `settings.json` 里
   `memory.trim_working_set` 设为 `false` 即可。

```json
"memory": { "trim_working_set": true, "idle_seconds": 120 }
```

### 关于「打包成 exe」的现实

打包不会让它变轻：PyInstaller 只是把 CPython 一起塞进 exe，运行时还是同一个解释器。

| 方案 | exe 体积 | 内存（空闲 / 使用中） | 代价 |
|---|---:|---|---|
| 现在（脚本 + pythonw） | — | 2.5 / 30 MB | 目标机要装 Python |
| PyInstaller **onedir** | 10~14 MB | 2.5 / 32 MB | 一个文件夹；推荐 |
| PyInstaller **onefile** | 10~14 MB | 4 / 36 MB | 每次启动解压到 TEMP，慢 2~3 秒 |
| C 重写（Win32 直调） | **0.1~0.2 MB** | **3~5 MB** | 要装编译器 + 重写全部 UI |

前两条是「同样的东西换个包装」，只有第三条是量级变化。若真要极致轻量，
协议字节表、卡片布局、菜单/通知逻辑都已在本文档里写清楚，属于机械翻译。

## 排错

- **图标不见了**：点任务栏的 `^`，把电池图标拖出来常显
- **鼠标一直显示 `--`**：接收器每 48 秒才推一帧，等一会儿即可（现在是实时接收，
  有帧马上就会刷出来）；仍无数据就动一下鼠标唤醒，并确认已和这台接收器配对
- **键盘显示 `--` 且提示休眠**：按一下键盘唤醒，最迟等下一次 10 分钟查询
- **看日志**：托盘右键 → 「查看日志」；文件在 `%TEMP%\2.4g_battery_tray.log`
  （pythonw 没有控制台，运行日志写到这里；文件带 UTF-8 BOM，记事本打开中文不乱码）
- **没收到低电量通知**，按这个顺序查：
  1. 看日志里有没有 `低电量提醒: xxx 18%` 这一行
     - **有这行但没横幅** → 通知被系统层屏蔽了：检查「设置 → 系统 → 通知」是否允许，
       以及是否开着勿扰/专注助手。程序那一侧已经发成功了。
     - **没有这行** → 提醒根本没触发：确认右键菜单里「低电量提醒」是勾上的、
       确认电量确实跌破了 `settings.json` 里的 `threshold`
  2. 右键菜单勾选一次「低电量提醒」——开启时会立刻弹一条**自检通知**，
     用它来判断「通知通道通不通」，不用真等电量掉下去

## 十个容易踩的坑（改代码前先看）

1. **后台进程拿不到前台，弹出菜单会"活不过来"**
   托盘程序是被动响应的后台进程，直接 `SetForegroundWindow` 会被系统静默拒绝；
   结果 `TrackPopupMenu` 的模态循环收不到鼠标点击，菜单显示出来却点了没反应。
   必须临时 `AttachThreadInput` 挂到当前前台线程再抢焦点 —— 见 `wsgui.force_foreground()`。
   同一个原因也会让弹出面板刚显示就被判定失焦而自动隐藏。

2. **`TrackPopupMenu` 不加 `TPM_RETURNCMD` 就拿不到选中项 id**
   默认它只返回 `TRUE/FALSE`，选中项是通过 `WM_COMMAND` 送出的；
   本程序不处理 `WM_COMMAND`，不加这个标志等于所有菜单项都失效。

3. **"缓存值"不能算作新数据**
   鼠标驱动读不到新帧时会把上次的值原样返回。如果这种返回也被当成"刚读到"，
   时间戳会被反复顶到当前时刻，界面上永远是「刚刚」——这个字段就彻底失去意义了。
   所以 `Reading.fresh` 用来区分"设备刚发的"和"我复述上次的"，只有前者才推进 `updated`。

4. **x64 下 GDI/USER 句柄必须按 32 位读**
   这些句柄本来就是 32 位值，系统返回时高 32 位是未定义的。用 `c_void_p` 当 `restype`
   会把符号扩展位一起读进来，拿到一个**非法句柄**，之后 `SelectObject` / `AlphaBlend`
   之类全部静默失败（表现是「画了但屏幕上什么都没有」，错误码 87）。
   本项目统一用 `wsgui.HANDLE32`（`c_uint32`）读所有句柄。

5. **本机 `AlphaBlend` 贴不了 32 位 DIB 源位图**
   带 alpha 的 `CreateDIBSection` 做源、哪怕参数完全合法，`AlphaBlend` 和
   `GdiAlphaBlend` 都稳定返回 `ERROR_INVALID_PARAMETER`（同样的 DC 用 `BitBlt` 却正常）。
   绕开办法：图标底下的颜色是已知的（白 / `#F4F9FE`），直接把「预乘图标 + 底色」
   算成不透明像素，再用 `BitBlt` 贴上去 —— 效果和真实 alpha 混合一致，还没有这个坑。

6. **`WM_ACTIVATE` 靠不住，收起面板要用鼠标钩子**
   卡片是 `WS_POPUP`，且托盘程序是被动响应的后台进程，`SetForegroundWindow`
   很容易被系统拒绝 —— 一旦没拿到激活态，点其他窗口就**不会有** `WA_INACTIVE`
   送过来，面板会一直挂着（用户实测就是这个现象）。
   改用 `WH_MOUSE_LL` 低级钩子，在鼠标按下时判断坐标是否在卡片矩形外。
   注意两点：钩子回调里不能直接隐藏窗口或卸载自己（会重入），
   要通过 `PostMessage` 交回主循环；回调函数对象必须保存引用，
   否则被 GC 回收后系统调用野指针会让整机鼠标卡顿。

7. **`GetModuleHandleW` 不声明 `restype` 会拿到负数**
   ctypes 默认按 `c_int` 读返回值，x64 下模块基址被截断成 `-962199552`。
   拿这个值当 `HINSTANCE` 去 `SetWindowsHookExW` 会报 `err=126`
   （`ERROR_MOD_NOT_FOUND`），钩子装不上、面板就永远不会自动收起。

8. **发气泡通知时 `uVersion` 只能是 0，且字符串要手动切到 63 / 255**
   `NOTIFYICONDATAW` 里 `uVersion` 和老接口的 `uTimeout` 是同一块内存。一旦设成
   `NOTIFYICON_VERSION_4`，回调语义会变成「`wParam` 带坐标、`lParam` 低字是 `NIN_*`」，
   `_on_tray_msg` 里 `ev = lparam & 0xFFFF` 的整套解析全部错位 —— 左键、右键、
   点外部收起会一起失效。另外 `szInfoTitle` / `szInfo` 是定长 `wchar` 数组，
   填满 64 / 256 虽然不抛异常，但**没有 NUL 结尾**，shell 会继续往后读到
   `uVersion` 等字段去，结果是乱码或整条通知失败。必须切到 63 / 255。
   还有一点：`NIF_INFO` 只能放进独立的 `Shell_NotifyIcon` 调用里，
   绝对不能加进被 800ms 定时器驱动的那个 `_notify()`，否则会变成通知风暴。

9. **生成 `.vbs` 时别手拼引号，也别用文本模式写文件**
   开机自启那个脚本是程序自己生成的，最早的写法踩了两个坑，直接导致开机弹窗：
   * 手拼成 `sh.Run """a"" """b"""`，引号数是 **11（奇数）**，VBScript 解析到行尾
     字符串还没闭合 → 报 **「语句未结束」800A0401**。正确做法是先把整条命令行
     拼成 `"exe" "script"`，再把里面每个 `"` 翻倍，最后外面包一对引号。
   * 用 `open(..., "w")` 写：文本模式会把 `\n` 再翻译成 `\r\n`，而我们写的本来就是
     `\r\n`，于是落盘成 `\r\r\n` —— 行号被算翻倍，报错指向根本不存在的「第 5 行」，
     排查方向直接被带偏。必须用 `"wb"` 二进制写。
   * 路径含中文（`2.4G电量托盘`），最终用 **UTF-16 带 BOM** 写，不依赖系统 ANSI 代码页；
     Windows Script Host 认 BOM，双击 / cscript / 开机自启都能正常执行。

10. **`.vbs` 存成 UTF-8 就必定打不开**
    Windows Script Host **只认 ANSI 和 UTF-16（带 BOM）**，遇到 UTF-8 的 `EF BB BF`
    BOM 会把它当三个非法字符，直接报 **「无效字符 / 行 1 / 字符 1 / 800A0408」**。
    本项目的 `启动.vbs` 就栽过一次（原来是 UTF-8 BOM，双击就弹窗）。
    规则：**所有 `.vbs` 一律 UTF-16 LE + BOM**；`.bat` 反过来要**纯 ASCII**，
    带 BOM 会让 cmd 把首行当成命令的一部分。
    改完跑 `python tray\_dev\_dev_vbs_check.py` 一键体检（编码 / 换行 / 引号）。
